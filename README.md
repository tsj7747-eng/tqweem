# منصة شواهد التقويم المدرسي الخارجي

منصة عربية لإدارة شواهد وأدلة التقويم المدرسي الخارجي، برابط واحد وصلاحيات حقيقية:
فريقك يعدّل ويرفع، وفريق التقويم يطّلع فقط.

---

## ما ستحصل عليه

- رابط دائم مثل: `https://اسم-حسابك.github.io/tqweem/`
- تسجيل دخول ببريد وكلمة مرور لكل شخص
- ثلاثة أدوار: **مشرف** و**محرِّر** و**مُشاهد**
- الملفات محفوظة في مساحة خاصة لا تُفتح إلا بتسجيل دخول
- لوحة جاهزية، وسجل نشاط يوضح من عدّل ماذا، وتقرير A4 للطباعة

---

## الملفات في هذه الحزمة

| الملف | وظيفته |
|---|---|
| `index.html` | البرنامج نفسه |
| `config.js` | مكان لصق مفتاحي Supabase — **الملف الوحيد الذي تعدّله** |
| `supabase_schema.sql` | يبني الجداول والصلاحيات ويعبّئ الشواهد الـ52 |
| `README.md` | هذا الدليل |

## الخطوة 1: أنشئ مشروع Supabase

1. ادخل `supabase.com` وسجّل الدخول بحساب GitHub الذي لديك.
2. **New project** ← اسم المشروع `tqweem` ← اختر كلمة مرور لقاعدة البيانات واحفظها ← المنطقة: اختر الأقرب (فرانكفورت أو سنغافورة).
3. انتظر دقيقتين حتى يجهز المشروع.

## الخطوة 2: ابنِ قاعدة البيانات

1. من القائمة الجانبية: **SQL Editor** ← **New query**.
2. افتح ملف `supabase_schema.sql`، وانسخ **كل** محتواه، والصقه.
3. اضغط **Run**. يجب أن تظهر رسالة نجاح.
4. للتأكد: **Table Editor** ← ستجد جدول `evidence` وفيه 52 صفًا.

## الخطوة 3: أوقف تأكيد البريد

1. **Authentication** ← **Sign In / Providers** ← **Email**.
2. أطفئ خيار **Confirm email** ثم احفظ.

> السبب: ستنشئ الحسابات بنفسك، فلا حاجة لرسائل تأكيد قد لا تصل.

## الخطوة 4: انسخ المفتاحين

1. **Project Settings** ← **API**.
2. انسخ **Project URL** و **anon public**.
3. افتح `config.js` بأي محرر نصوص والصقهما مكان العبارتين العربيتين، واحفظ.

> مفتاح `anon` مصمَّم ليكون ظاهرًا في المتصفح، والحماية الحقيقية من سياسات RLS التي نفّذتها في الخطوة 2.
> **لا تضع مطلقًا مفتاح `service_role` هنا** — فهو يتجاوز كل الصلاحيات.

## الخطوة 5: انشر على GitHub Pages

1. في GitHub: **New repository** ← الاسم `tqweem` ← **Public** ← **Create**.
2. **Add file ← Upload files** ← اسحب الملفات الأربعة ← **Commit changes**.
3. **Settings ← Pages** ← تحت *Branch* اختر `main` و `/ (root)` ← **Save**.
4. انتظر دقيقة أو دقيقتين، ثم حدّث الصفحة ليظهر الرابط في الأعلى.

> المستودع عام، لكن الملفات المرفوعة داخل المنصة **ليست فيه** — هي في Supabase خلف تسجيل الدخول.
> الظاهر للعموم هو شكل البرنامج فقط، لا بيانات مدرستك.

## الخطوة 6: أنشئ المستخدمين وحدد أدوارهم

1. **Authentication ← Users ← Add user ← Create new user**.
2. اكتب البريد وكلمة مرور مؤقتة، وفعّل **Auto Confirm User**.
3. كرّر لكل عضو في فريقك وفي فريق التقويم.
4. **Table Editor ← profiles**: ستجد صفًا لكل مستخدم أُنشئ تلقائيًا بدور `viewer`.
5. غيّر عمود `role`:
   - `superadmin` — لك أنت إن كنت تشرف على أكثر من مدرسة
   - `admin` — مدير المدرسة الواحدة
   - `editor` — لأعضاء الفريق الذين يرفعون ويعدّلون
   - `viewer` — لفريق التقويم (لا يُغيَّر، فهو الافتراضي)
6. غيّر عمود `school_id` وضع فيه معرّف مدرسة الشخص، منسوخًا من جدول `schools`.
   صاحب `superadmin` لا يحتاجه لأنه يرى كل المدارس.

**كل مستخدم جديد يبدأ «مُشاهد» تلقائيًا. الترقية قرار يدوي منك.**

## تعدد المدارس

المنصة تدعم أكثر من مدرسة في نفس الرابط، وكل مدرسة مستقلة تمامًا:
شواهدها وملفاتها وسجل نشاطها لا يراها أحد من مدرسة أخرى.

**لإضافة مدرسة**، نفّذ سطرًا واحدًا في `SQL Editor`:

```sql
select public.create_school('ابتدائية الأمير سلطان');
```

تُنشأ المدرسة ومعها الشواهد الـ52 جاهزة. أو أضفها من داخل المنصة عبر تبويب «المدارس»
إن كان دورك `superadmin`.

**العزل مفروض من قاعدة البيانات لا من الواجهة.** حتى لو حاول مستخدم استدعاء بيانات
مدرسة أخرى مباشرة، الخادم يرفض. والملفات مخزّنة كل مدرسة في مجلد باسم معرّفها،
وسياسة التخزين تمنع تجاوز المجلد.

**صاحب `superadmin`** يرى في الأعلى قائمة يتنقل بها بين المدارس، وله تبويب «المدارس»
فيه مقارنة نسب الجاهزية بينها.

**ترقية تركيب قديم:** إن كنت شغّلت الإصدار السابق ذا المدرسة الواحدة، شغّل ملف
`supabase_schema.sql` الجديد كما هو. سيُنشئ مدرسة واحدة باسم مدرستك الحالي ويَنسب
إليها كل بياناتك القائمة دون فقد شيء.

## الخطوة 7: جرّب

افتح الرابط، سجّل الدخول بحسابك، واملأ بيانات المدرسة من تبويب الإعدادات.
ثم افتح الرابط في نافذة تصفح خفي وسجّل بحساب `viewer` وتأكد أن الأزرار لا تظهر له.

## ملاحظات مهمة

**قائمة الشواهد اجتهادية.** المجالات الأربعة والمعايير العشرة معتمدة، أما تفاصيل الشواهد الـ52
فمصوغة من الممارسة الإدارية المعتادة. راجعها مقابل دليل الهيئة المعتمد وعدّلها من `Table Editor ← evidence`.

**حدود الباقة المجانية في Supabase:** مساحة تخزين محدودة (تكفي عادةً لمئات الملفات)،
والمشروع يُوقَف مؤقتًا إذا لم يُستخدم أسبوعًا كاملًا ويعود بالضغط على زر في اللوحة.
راجع صفحة الأسعار عندهم لأن الحدود تتغير.

**النسخ الاحتياطي:** صدّر نسخة JSON شهريًا من تبويب الإعدادات، واحتفظ بالملفات الأصلية عندك أيضًا.
لا تجعل المنصة النسخة الوحيدة من شواهدك.

**تنبيه:** إذا فشل تنفيذ سياسات مساحة التخزين في الخطوة 2 (القسم رقم 7 من ملف SQL)،
اضبطها يدويًا من **Storage ← Policies** على مساحة `evidence`.
